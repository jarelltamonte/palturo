PalTuro / For YouExhausted state
D-03

Seen every card? The deck says so, and hands over four exits.

Previously the last swipe left a blank canvas. The new state keeps a small pile of cards on screen, puts a note on the top card, and offers Explore, View Again, Browse, and Update Profile.

Why it happened

The deck had no terminal state. Once every candidate was skipped or requested, the list was empty and the page had nothing to draw.

How it is fixed

Seen cards are stored per account in deck_seen_v1_<userId>, so the exhausted state survives a reload and a new login. View Again clears that local set.

Explore is a person deck, not a skill list. It reuses the For You card and deals random people without end, so there is always a way to keep looking after the curated deck runs out.

PalTuro / BrowseDead ends
D-04

Browse hides what it cannot fill, and counts what it can.

Browse used to list every branch in the taxonomy, including branches with no mentors or no learners for the role you picked. Tapping one opened an empty category. Now the grid only lists branches with people, and each card states the count.

Cause

The taxonomy is static. It was rendered without checking whether any profile matched the selected role, so the page promised supply it did not have.

Fix

Counts are derived from the loaded people for the active role, empty branches are dropped, and the category page filters empty child skills while showing an avatar preview at the top.

PalTuro / notificationsBadge and banners
B-01

The Requests badge now counts requests, and banners survive their own host.

Two separate faults sat behind the notification complaints: the badge was fed by the whole unread feed, and the match banner crashed because its close button needed an Overlay that does not exist above the Navigator.

Badge and read state
  • Requests badge uses unread incoming connection requests only.
  • Accepting or declining marks that request notification read.
  • Tapping a banner marks its notification read.
  • Realtime handles insert, delete, and update, so a withdrawn request and a read on another device both land here.
Banner crash

IconButton(tooltip:) builds a Tooltip, which looks up an Overlay. The banner host sits above the Navigator, so that lookup threw. Replaced with a Semantics(label:) wrapper, which needs no Overlay.

Pinned by banner does not require an Overlay ancestor.

Banners also respect notification preferences, are enriched with the person and skill behind a realtime row, and are removed when the notification is withdrawn server-side.

One table for the four notification kinds

KindCounts in badgeBannerRealtime source
Connection requestYes, unread onlyShown unless Requests is openInsert on notifications
Request accepted or declinedNoShown, enriched with the chatInsert on notifications
Feedback readyNoShown, respects preferencesInsert on notifications
Withdrawn requestDrops immediatelyExisting banner removedDelete on notifications

PalTuro / authenticationKeyboard
B-02

The primary button no longer hides behind the keyboard.

On a phone the Log In and Sign Up buttons lived in a bottom bar. When the keyboard opened, that bar was covered and the form could not be submitted without dismissing it first.

Cause

The actions were outside the scrollable body, so the inset that the keyboard adds moved the body but not the bar.

Fix

Log In, Forgot Password, Create new account, and Sign Up now sit inside the form and scroll with it. Login uses resizeToAvoidBottomInset on mobile and keeps the web scroll workaround.

Regression tests at 390 x 844 with a 300 px keyboard. Login asserts that Log In, Forgot Password, and Create new account all end above the keyboard; register asserts the same for Sign Up. Both fail on overflow or layout exceptions.

PalTuro / chat deletionMessage and conversation
B-03

Long press a message to delete it. Long press a chat to clear it.

Message deletion is sender-only. Conversation deletion is available to either participant, clears the messages, and deliberately keeps the Pal connection, so the relationship is not lost with the history.

Backend

delete_message(uuid) checks the caller is the sender. delete_conversation(uuid) checks the caller is a participant, deletes the messages, and leaves the connection row in place.

Defect found in live testing

The first conversation delete failed because it reset the NOT NULL read timestamps to null. It now sets them to now(), and the live run clears the thread while the connection stays accepted.

Rules the UI enforces

ActionWho can do itWhat survives
Delete messageThe sender onlyThe row, its timestamp, and a "Message Deleted" bubble for both people
Delete conversationEither participantThe connection, its status, and both profiles. Messages are removed
Peer viewNot applicableThe ghost appears without a refresh, over Realtime UPDATE

PalTuro / chat integrityTombstones
B-04

Deleted text keeps its place, so no one can edit the past.

Removing the row let a sender erase a statement and leave the other person's reply hanging, which is exactly how a thread gets taken out of context. A deleted message is now a tombstone: the body is replaced with Message Deleted and deleted_at is set. The bubble is gray and italic, and cannot be tapped, long-pressed, or copied.

Server

20261113000300_message_tombstones.sql adds deleted_at, rewrites delete_message as an update, and returns deleted_at from get_conversation. Both clients read the same row.

Client

The room treats a row as deleted when deleted_at is set or the body is the ghost text. The local delete updates the row in place instead of removing it, and Realtime UPDATE paints the peer's tombstone without a refresh.

B-05

And the view lands on the newest message, not one line above it.

A lazy list reports an estimated maxScrollExtent on the frame a new bubble is inserted, then refines it once that bubble is laid out. The single jump used the estimate, which is why the last line sat just below the composer. A second post-frame jump lands on the true bottom. Live check: a sent message now sits fully above the composer with the thread scrolled to it.
